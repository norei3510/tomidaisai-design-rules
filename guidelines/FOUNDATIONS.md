# FOUNDATIONS — 何を選ぶか、なぜそうするか

> 答える問い: **この画面で、どの色・文字・余白・形を選ぶべきか。その理由は何か。**
> 値そのものは `tokens/*.json` が正。本書は値を再掲せず、トークン名で書く。
> 基準: 色・余白・操作の値は来場者企画（unifes26-vp `front/`）の 2026-10-21 時点の実装。当日ページ（TOP・企画一覧・タイムテーブル・マップ）の書体・形・組み方は v0.3.0 で新しく定めた【暫定】。

## 1. 原則

富大祭のページは、**会場を歩きながら片手のスマートフォンで見る**ことを前提にする。迷ったら次の順で判断する。

1. **読める**: 屋外・移動中でも読める大きさとコントラストにする
2. **押せる**: 親指で確実に押せる大きさと間隔にする
3. **次が分かる**: 1画面で「いまどこか」「次に何をするか」を1つに絞る
4. **富大祭らしい**: 水色の下地、紺の罫線、橙の「いま・ここ・押す」、見出しと数字の書体で、どのページも同じ祭りのサイトと分かる
5. **情報が飾り**: 時刻・場所コード・件数を大きく見せることで画面を作る。それ以外の装飾は足さない

### 1.1 世界観
- 当日ページは「**会場の案内サイン × 当日の紙パンフレット**」。白いカードを並べたアプリ画面ではなく、罫線と大きな文字で組んだ案内板・プログラム表として作る
- 水色の下地は空・未来・明るさ、橙は「いま・ここ・押してほしい場所」を表す
- 当日ページは1ページ1コンテンツ（TOP・企画一覧・タイムテーブル・マップ）。そのコンテンツ自体を最初の画面の主役にし、紹介文・ヒーロー画像・キャッチコピーで前置きしない
- 公式キャラクター「トミー君」は来場者企画の案内役。他ページで使う条件は `components/specific/guide-speech.md`
- 来場者企画の「富大祭3190」の物語・セリフ・問題は共通ルールに含めない

### 1.2 AIっぽく見せない
生成ツールが出しがちな「どこにでもある画面」を避ける。次の5つが揃うと、どの祭りのサイトか分からなくなる。具体的な禁則は `PROHIBITIONS.md` の「AIっぽさ」。

| 避ける形 | 代わりにすること |
|---|---|
| 同じ大きさの白い角丸カード＋やわらかい影を並べる | 罫線と余白で区切る。カードは「押せる1件」と「1画面1つの主役」だけ（§5） |
| 英字アイブロウ＋h1＋1行説明の定型の見出し | h1 は大きな和文1つ。説明は件数・日時など具体的な値だけ（PAGE_LAYOUT_GUIDE §2） |
| 1書体・小さいサイズ差で全部を組む | 和文見出し・数字・本文の3書体で、見出しと数字を本文の2倍以上にする（§3） |
| 見出しごとのアイコン・意味のない装飾 | アイコンは道案内だけ（§6）。装飾の代わりに場所コード・時刻を大きく見せる |
| 中身のない紹介文・作った数字 | 実データだけを書く。未確定は「準備中」（WRITING_GUIDE §5） |

## 2. 色

### 2.1 面積の比率（目安）

```
bg-page（水色）      ████████████  約60%  画面全体の下地
bg-surface（白）     ██████        約25%  表・一覧の帯・入力・ナビ
青（main系）          ██            約8%   ヘッダー・サイン板・場所コード・副操作・リンク
橙（accent系）        █             約4%   いま・ここ・主要操作だけ
紺（ink）             █             約3%   本文の文字・罫線
```

- 水色で広く覆い、白い帯で内容を載せ、紺の罫線で区切る。橙は「いま・ここ・押す」だけに使う
- 比率は実装から読み取った傾向で、厳密な規定ではない【暫定】

#### 橙を使う場所（「いま・ここ・押す」）
| 意味 | 例 | トークン |
|---|---|---|
| いま | 現在時刻の線、「開催中」の印、TOP の現在時刻 | 線・図形は `graphic-now`、白文字を載せる印は `status-now`、文字は `text-accent` |
| ここ | マップで選んだ建物、ボトムナビの選択中 | 枠・図形は `graphic-now`、文字は `text-accent` |
| 押す | 主要操作のボタン（**1画面に1つ**。2つ目以降は青か枠線ボタン） | `action-primary` |

- 当日ページは毎ページに「いま」か「ここ」がある（TOP・タイムテーブルは現在時刻、企画一覧は開催中の印、マップは選んだ建物）。そのため、主要操作がないページでも橙が入る
- 上の3つ以外（見出しの飾り線・分類タグの色分けなど）に橙を使わない。v0.2.0 の暫定対応（企画一覧の見出し下の橙の線）は、この表に置き換える

### 2.2 文字色と下地の組み合わせ

コントラストは本文 4.5:1 以上、18px以上の太字・アイコン・枠は 3:1 以上を守る。

| 文字（semantic） | 白い面 | 水色の下地 | 判断 |
|---|---|---|---|
| `text-primary` | 11.9:1 | 9.3:1 | どこでも使える |
| `text-link`（青） | 6.1:1 | 4.7:1 | どこでも使える |
| `text-accent`（橙） | 5.4:1 | 4.2:1 | 白い面ではどこでも。水色の下地では18px以上の太字だけ |
| `text-secondary` | 4.5:1 | 3.5:1 | **白い面の上だけ**。水色の下地には置かない |
| `text-danger` | 7.2:1 | — | 白い面の上でエラー文に使う |
| `graphic-main` / `graphic-accent` | 4.2:1 / 3.1:1 | — | **文字に使わない**。枠・図形・装飾線だけ |

- 白文字を載せる面は `action-primary`・`status-now`（橙の濃色）と `action-secondary`・`bg-sign`・`bg-header`（青の濃色）だけ。`graphic-accent`（`#F26A00`）の上に白文字を載せない
- 状態を色だけで伝えない。達成済みは塗り＋外形、エラーは枠色＋文、選択中は色＋太字＋ピル

### 2.3 ダークモード
対応しない【未定】。`prefers-color-scheme: dark` でも同じ配色で表示する。

## 3. 文字

### 3.1 書体は役割で3つに分ける

| 役割 | トークン | 書体 | 使う場所 |
|---|---|---|---|
| 和文の見出し | `font-family.display` | りょうゴシック PlusN（Adobe Fonts）。`bold`（700）と `heavy`（800）だけを使う | h1、セクション見出し、入口の札、建物名の大見出し |
| 数字・英字 | `font-family.numeral` | DIN 2014（Adobe Fonts）。表など幅が狭い所は細身の `numeral-narrow`（DIN 2014 Narrow） | 時刻、場所コード、件数、番号、日付の数字 |
| 本文 | `font-family.body` | Noto Sans JP | 本文、補足、ボタン、入力、ナビ、チップ |

- 1ページで使う書体はこの3つまで（DIN 2014 と DIN 2014 Narrow は同じ書体の幅違いとして1つに数える）。数字の書体は、道路標識・案内サイン用に作られた DIN を使い、方向（§1.1）と合わせる。来場者企画のセリフ用書体（明朝・丸ゴシック）は物語の演出用で、当日ページには使わない
- display は 22px（`xl`）以上だけに使う。小さい文字・長い文には使わない
- numeral は数字と半角英字だけに使う。和文が混ざる要素では、数字の部分だけを `<span>` で分けて当てる
- 字詰め（`font-feature-settings: "palt"`）は display の見出しだけにかける。本文にはかけない
- 時刻・件数など縦にそろえて読む数字は等幅（`font-variant-numeric: tabular-nums`）にする
- 書体は Adobe Fonts の当日ページ用キット `bqk8omc` で読み込む（JavaScript の埋め込みコードを `<head>` の CSS より前に置き、`scriptTimeout` は 3000）。来場者企画のキット `dlw1fic` は来場者企画用の書体まで読み込むので使わない。配信するドメインをキットに登録する【要確認】。キットが届かなくても、トークンの後ろの書体（Noto Sans JP の `black`・Arial）で読める

### 3.2 サイズと役割

本文は `font-size.body`（16px）・`line-height.body`（1.7）。**12px（`xs`）未満は使わない**。

| 役割 | サイズ | 書体・太さ | 行間 |
|---|---|---|---|
| 主役の数字（TOP の現在時刻） | `5xl` | numeral `bold` | `display` |
| 主役の見出し・大きい数字（使うときは1画面1か所） | `4xl` | display／numeral `bold` | `display` |
| 画面見出し（h1） | `3xl` | display `heavy` | `display` |
| セクション見出し（h2）・建物名・TOP の入口の札 | `xl` | display `bold` | `heading` |
| 一覧の名前・カードの見出し | `lg` か `body` | body `bold` | `heading` |
| 本文・ボタン・入力 | `body` | body `regular`／ボタンは `bold` | `body` |
| 補足 | `sm` | body `regular` | `body` か `compact` |
| 注記・ナビ・チップ・場所コードの札 | `xs`〜`sm` | body `regular`（札は numeral `bold`） | `compact`（ナビ・札は `tight`） |

- **見出しは本文の2倍以上**（h1 は `3xl` 以上）。22px 前後の見出しを最大の文字にしない
- 1画面で使うサイズは5段階までにする（TOP の現在時刻など `5xl` の主役の数字は数えない）。そのうえで `lg` と `xl` のような近い段を同じ画面で両方使わない（差が見えない段を作らない）
- 本文の1行は全角35字前後を上限にする（`content-max` の幅で自然に収まる）
- 数字と単位、日付と曜日、時刻の範囲は改行させない
- 英字の小見出し（アイブロウ）は使わない。`eyebrow` の字間は来場者企画との互換のために残す

## 4. 余白

- すべて `space` トークン（4の倍数）から選ぶ。中間の値を作らない
- **画面の左右は `space-4`（16px）**。カードの内側も `space-4`、大きいカードは `space-6`
- 近いものは近く、違うものは遠く: 同じカード内の行は `space-2`〜`space-3`、カード同士は `space-3`〜`space-4`、セクション間は `space-6`〜`space-8`
- ページ末尾はボトムナビの上に `space-8` を残す

## 5. 形と影

### 5.1 カードではなく罫線で区切る
- 情報のまとまりは、紺の罫線（`border-strong`）と余白で区切る。白い面は「帯」（全幅か本文幅いっぱいの白い面）として敷き、角丸カードを並べない
- 見出しの下に `border-strong` の2px、行と行の間に `border-default` の1px。表の外枠も `border-strong` の2px
- 白い角丸カードを使うのは、①押せる1件をそれだけで見せるとき、②ダイアログ、の2つだけ

### 5.2 サイン板（主役の枠・1画面に1つ）
- 画面で一番見てほしい1つ（TOP の「いま開催中」、マップで選んだ建物の情報など）だけを、構内の案内板と同じ組み方で囲む
  - 上部に `bg-sign`（青の濃色）の見出しの帯。見出しは白文字（`text-on-fill`）の display 書体 `font-xl`、件数は numeral 書体
  - 外枠は 2px `border-sign`（帯と同じ青）、中は白（`bg-surface`）、影なし
- 2つ以上に使わない。サイン板の中の小見出しは、帯ではなく罫線（`border-strong` 2px）で区切る
- サイン板の中の場所コードの札は、帯の上では白地に青文字に反転させる（`components/base/place-code.md`）

### 5.3 角丸と影
| 対象 | 角丸 | 影 |
|---|---|---|
| 情報ブロック・白い帯・サイン板・場所コードの札・押せる行のまとまり | `block`（4px） | なし |
| ボタン・チップ・バッジ・ナビの選択ピル | `pill` | なし |
| 入力欄 | `input` | なし |
| ダイアログ | `card` | `shadow-2` |

- `shadow-1`（やわらかい影）と、`card`・`modal` の角丸を当日ページの一覧・見出しまわりに使わない（来場者企画との互換のために残す）
- 枠線は `border-default` の1px、入力・枠線ボタンの2px（青）、罫線の2px（`border-strong`）、サイン板の外枠の2px（`border-sign`）の4種類
- 当日ページでは、ダイアログ以外に影を使わない。浮かせて目立たせる代わりに、帯の色と罫線の太さで階層を作る

## 6. アイコン

- 24×24 の viewBox、塗りなしの線アイコン、線幅 `icon.stroke`（1.8）、線端と角は丸
- 選択中は線幅 `icon.stroke-active`（2.2）
- 1ページで1系統だけ使う。塗りと線を同じ階層で混ぜない。絵文字を機能アイコンにしない
- 見出しごとにアイコンを付けない。アイコンは道案内（矢印・場所・外部リンク）と状態を示すときだけ
- 場所は、アイコンより先に場所コードの札（`components/base/place-code.md`）で示す

## 7. 動き

- 動きは状態の変化（押した・開いた・正誤）を伝えるときだけ使う
- 押下は `scale.press` を `duration.press`、hover・色の変化は `duration.base`、`easing.standard`
- 繰り返しアニメーションは「いま待っている／探している」ことを示す1か所だけ（例: QR読み取りの走査線）
- `prefers-reduced-motion: reduce` では動きを止める（`tokens.css` が duration を 0 にする）

## 8. 端末と画面サイズ

| 項目 | ルール | 分類 |
|---|---|---|
| 主な端末 | スマートフォン縦持ち。デザイン基準は `frame.design-width` × `design-height`（390×844） | 【確定】 |
| 本文の幅 | 1カラムの本文は `content-max`（480px）まで。広い画面では中央寄せ | 【暫定】 |
| 広い画面 | 768px以上の一覧は2列、`content-wide-max` まで。ヘッダーとナビの背景は全幅 | 【暫定】 |
| 確認する幅 | 375 / 768 / 1024 / 1440px。375px で横スクロールが出ない | 【確定】 |
| セーフエリア | 四辺の `env(safe-area-inset-*)` を考慮する。ヘッダー・ナビに隠れる部分を本文の高さに含めない | 【確定】 |
| スクロール | 共通ページは通常の縦スクロール。来場者企画の問題画面の「スクロールさせない」は企画固有で、共通にしない | 【確定】 |

## 9. アクセシビリティ

- すべての操作はキーボードで届き、`focus-ring` の3px枠（offset 3px）が見える
- 押せる要素は `touch-min`（44px）四方以上、隣との間は `space-2` 以上
- 画像には内容を表す `alt`、装飾画像は `alt=""`
- 文字サイズを端末設定で大きくしても、ボタンの文字が切れない（`white-space: nowrap` は短いラベルだけ）
- 動きを減らす設定に従う
