# layout-index — 骨格テンプレートの選び方

> 答える問い: **新しいページは、どの骨格から組み始めるか。**
> どの骨格も「共通ヘッダー → 通知バー（任意） → 本文（縦スクロール） → ボトムナビ」。組み方の原則は `guidelines/PAGE_LAYOUT_GUIDE.md`。

| 骨格 | ファイル | 本文の構成 | 合うページ |
|---|---|---|---|
| 一覧 | `list.html` | 見出し → 絞り込みチップ → リスト（768px以上で2列） | 企画一覧、ステージの演目、出展一覧 |
| 詳細 | `detail.html` | バッジ・見出し → 画像（比率を保つ） → 基本情報カード → 主な操作 → アコーディオン | 企画詳細、場所の案内、お知らせ詳細 |
| 操作が主役 | `action.html` | 見出し・案内 → カード型ボタン1つ → 代わりの入力 → 控えめな操作 | QR・受付・スタンプ・アンケートの入口（来場者企画のQR案内画面と同じ形） |
| 結果・空・エラー | `message.html` | 中央に印 → 見出し → 1〜2文 → 次の操作 | 完了、見つからない、通信できない |

## 選び方
1. ページの目的が「探す」→ 一覧、「知る」→ 詳細、「何かをする」→ 操作が主役、「結果を伝える」→ 結果
2. 2つに当てはまるときは、最初の画面で一番見せたいほうを選ぶ
3. どれにも当てはまらないときは、一番近い骨格から組み、違う点を `pages/<ページ名>.md` に書く

## 使い方
- `skeleton.css` は骨格を確かめるための参考実装。`tokens/tokens.css` の後に読む
- `［ ］` と破線の枠（`.ph`）は差し替える場所。実際のページでは消す
- `message.html` の状態切り替えチップは確認用。実際のページでは消す
- マップ・タイムテーブルのような特殊な画面は骨格を用意していない【未定】。詳細の骨格から組み、判断を `pages/` に残す
