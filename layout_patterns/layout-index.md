# layout-index — 骨格テンプレートの選び方

> 答える問い: **新しいページは、どの骨格から組み始めるか。**
> どの骨格も「共通ヘッダー → 通知バー（任意） → 本文（縦スクロール） → ボトムナビ」。組み方の原則は `guidelines/PAGE_LAYOUT_GUIDE.md`。

| 骨格 | ファイル | 本文の構成 | 合うページ |
|---|---|---|---|
| 当日TOP | `top.html` | 現在時刻（`5xl`）→ サイン板（開催中・次に始まる）→ 入口の札（企画一覧・タイムテーブル・マップ） | 当日のトップページ |
| 一覧 | `list.html` | 見出し（件数）→ 絞り込みチップ → 場所コードごとの索引（行の左端に時刻、768px以上で2列） | 企画一覧、出展一覧 |
| タイムテーブル | `timetable.html` | 見出し → 日付 → 767px以下はステージを切り替えて時刻順の行、768px以上は時刻×ステージの格子。どちらも現在時刻の印つき | ステージのタイムテーブル |
| マップ | `map.html` | 見出し → 地図（幅いっぱい・比率を保つ）＋［地図を拡大する］→ 場所コードの札 → 選んだ建物の企画（サイン板） | 会場マップ |
| 詳細 | `detail.html` | バッジ・見出し → 画像（比率を保つ） → 場所と時間（罫線＋白い帯） → 主な操作 → アコーディオン | 企画詳細、場所の案内、お知らせ詳細 |
| 操作が主役 | `action.html` | 見出し・案内 → カード型ボタン1つ → 代わりの入力 → 控えめな操作 | QR・受付・スタンプ・アンケートの入口（来場者企画のQR案内画面と同じ形） |
| 結果・空・エラー | `message.html` | 中央に印 → 見出し → 1〜2文 → 次の操作 | 完了、見つからない、通信できない |

## 選び方
1. ページの目的が「探す」→ 一覧、「知る」→ 詳細、「何かをする」→ 操作が主役、「結果を伝える」→ 結果
2. 2つに当てはまるときは、最初の画面で一番見せたいほうを選ぶ
3. どれにも当てはまらないときは、一番近い骨格から組み、違う点を `pages/<ページ名>.md` に書く

## 使い方
- `skeleton.css` は骨格を確かめるための参考実装。`tokens/tokens.css` の後に読む
- `［ ］` と破線の枠（`.ph`）は差し替える場所。実際のページでは消す
- `message.html` の状態切り替えチップは確認用。実際のページでは消す
- 当日ページ（TOP・一覧・タイムテーブル・マップ）の骨格は v0.3.0 で追加した【暫定】。実データで組んだら、違った点を `pages/` に残す
- `timetable.html` の現在時刻の線は確認用の固定値（13:40）。実ページでは現在時刻から計算する（`components/base/now-marker.md` §2）
- 骨格は Adobe Fonts のキットを読まないので、見出しと数字は後ろの書体（Noto Sans JP・Arial・Arial Narrow）で表示される
- スマホ（767px 以下）とそれ以上で組み方が変わるのは `timetable.html` だけ。確かめるときは 390px と 1024px の両方で開く
